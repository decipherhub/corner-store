# Deployment-to-DEX Showcase Runbook

This runbook connects the production core implementation to the local RFQ DEX
showcase without treating demo fixtures as production onboarding evidence.

## What Is Connected

The local `DeployStack.s.sol` no longer builds a separate Corner Store core. It
calls the same `DeployProductionCore.deployCore()` seam used by the production
deployment workflow, then performs an explicitly separate local activation:

1. production core registries, engine, Router and enabled adapters;
2. demo-only ERC-3643/ONCHAINID asset and Mock TA facts;
3. demo-only Element, Recipe, Manifest, venue, maker and inventory activation;
4. one deployment artifact consumed by the CLI, RFQ backend, Operator API and
   Dashboard.

The resulting addresses prove integration continuity on local Anvil. They are
not production addresses, legal approval, issuer onboarding evidence or a Safe
execution record.

## Configure the Showcase

Copy and edit the versioned input:

```sh
cp services/toolkit/examples/corner-store.showcase.json corner-store.showcase.json
```

| Field | Meaning |
| --- | --- |
| `profile` | `buidl-like` or `reg-d` policy presentation |
| `mode` | `rfq` for the concise walkthrough; `full` also runs the AMM/lifecycle suite |
| `scenario` | injected local account, balance, pricing, QP and expiry fixtures |
| `runtime.bindHost` | local service bind address; the showcase accepts loopback only |
| `runtime.publicHost` | host used by the browser and local service clients |
| `runtime.*Port` | Anvil, RFQ backend, Operator API and Dashboard ports |

The scenario supplies test data. Contract addresses are never copied into this
configuration: they are generated by deployment and propagated through
`deployments/anvil-e2e.json`.

## Review Before Starting

```sh
scripts/showcase.sh --config corner-store.showcase.json --plan
```

Plan mode submits no transaction. Confirm the profile, scenario, ports, output
paths and the eight execution steps before the presentation.

## Run

```sh
scripts/showcase.sh --config corner-store.showcase.json
```

The runner executes this order:

1. validate configuration, scenario and local ports;
2. start a clean Anvil chain;
3. deploy the production core implementation;
4. inject and activate local token, identity, policy, venue and inventory
   fixtures;
5. write, preflight and onboard from the deployment artifact;
6. start the RFQ backend bound to that artifact;
7. start the Operator API and Dashboard with injected endpoints;
8. prove successful Router settlement and expected rejection paths.

Open the printed Dashboard URL. The top ribbon and Environment card identify
the core implementation, activation mode and Router address read from the live
artifact. Press `Ctrl-C` in the runner terminal to stop all child services.

## Values Injected at Each Boundary

| Boundary | Injected values | Source of truth |
| --- | --- | --- |
| deployment | profile, deterministic local accounts, initial balances | showcase + scenario JSON |
| demo activation | Mock TA claims, policy bindings, venue, maker and inventory | scenario + `DeployStack.s.sol` |
| service startup | RPC, artifact path, scenario path, bind/public hosts and ports | runner arguments |
| quote generation | maker, signer, price, TTL, nonce and exact deployed addresses | scenario + live artifact |
| settlement | taker, side, amounts and reviewed signed quote | Dashboard request |
| final compliance | current claim, policy, maker and Router state | live Anvil contracts |

## Production Handoff

For production, do not run this showcase against a public network. Use
`docs/deployment-production.md` to deploy the core through an external signer or
Safe, onboard a real ERC-3643/ONCHAINID asset with issuer evidence, activate a
legal-approved Manifest and configure production RFQ services. A production DEX
can retain the same artifact-driven service boundary, but must replace every
Mock TA, deterministic account, fixed pricing, in-memory nonce and demo
inventory component.
